# 思い出図書館

## 1. サービス概要

### このサービスはどんなサービスか

人生の転機となった本・映画・音楽などの作品と思い出を記録するライフログアプリです。同じ作品に対する過去と現在の感想を振り返り、自分の感情や価値観の変化に気づくことができます。

### 誰の、どんな課題を、どう解決するか

日々の忙しさの中で、自分の価値観や素直な感情を見失いがちな社会人を対象としています。心に残る作品との思い出を記録し、時間を置いて振り返ることで、自分が大切にしてきたことや変化したことに気づくきっかけを提供します。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

子どものころに読んだ本や絵本、漫画を大人になってから読み返したとき、以前とはまったく違う作品のように感じることがありました。昔は理解できなかった場面に共感したり、感情移入するキャラクターが変わったりして、作品を楽しむと同時に、自分自身の変化にも驚きました。

また、同じ作品を見た人と感想を語り合うと、着目する場面や感じ方の違いから、その人の考え方を知ることができます。作品そのものだけでなく、受け取る人や時期によって変わる体験も残せたら面白いと感じたことが、アイデアのきっかけです。

### 2-2. なぜそれが「気になった」のか

私は子どものころから自己分析に関心があり、自分の弱点を克服したい、自分を変えたいと考えてきました。一方で、挑戦を重ねても、遠回りばかりで前に進めていないように感じることがあります。

そんなとき、同じ作品に対する過去と現在の感じ方を比べられれば、自分が変わった部分や、ずっと大切にしている感情に気づけるのではないかと考えました。

---

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

作品を通じて得た感情や個人的な思い出を記録しても、後から同じ作品に対する感想と並べて振り返ることが難しいです。そのため、過去と現在の自分を比較する機会がありません。

### 3-2. 本当に解決したい課題は何か

- なぜ困るのか？  
  既存の読書管理サービスでは、作品の評価やレビューが中心になりやすく、その作品にまつわる個人的な思い出や素直な感情を残しにくいからです。
- それはなぜ困るのか？  
  記録の中心が「作品」になると、その作品に出会った当時の自分が何を感じ、何を大切にしていたかを振り返りにくいからです。
- それはなぜ困るのか？  
  日々の生活の中で自分の感情や価値観を確かめる機会が少ないと、今の自分が何を大切にしたいのか分からなくなることがあるからです。

**本当に解決したい課題：** 作品との思い出を手がかりに、過去と現在の自分の感情や価値観を振り返る機会をつくることです。将来的には、他の人の体験にも触れ、自分とは異なる感じ方を知る機会にもつなげたいです。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

**年齢設定**

- 年齢：20代後半の社会人
- 理由：社会に出て数年が経ち、仕事には慣れてきた一方で、これからのキャリアや生き方について考える機会が増える時期だからです。

**生活・状況設定**

- 生活・状況：現在の仕事や生活と、自分の理想との間にギャップや停滞感を覚えています。休日には本を読んだり、好きな作品を鑑賞したり、日記や手帳で考えを整理したりしています。
- 理由：作品に出会った当時の思い出と今の感想を比べることで、自分の変化や変わらず大切にしていることに気づくきっかけを得られるからです。

**環境設定**

- 環境：SNSは使っていますが、主に閲覧や検索が中心です。他人の目や評価が気になり、個人的な思い出や感情は投稿しにくいと感じています。
- 理由：まずは自分のために記録し、将来的には公開・非公開を選べるようにすることで、自分のペースで思い出を残したり共有したりできるようにしたいです。

### 4-2. 自分とユーザーの距離

**自分自身**

私は自己理解を深めたり、他の人の考え方を知って視野を広げたりすることに関心があります。また、新しいことに挑戦するときや環境が変わるときに、「この方向で大丈夫だろうか」と不安になることがあります。そうしたときに、自分がこれまで大切にしてきたことを振り返れる場所が欲しいと感じています。

### 4-3. 実際に使われる可能性について（需要・存在確認）

**まず最初に使ってくれそうな人は誰か？**

読書や作品鑑賞が好きで、日記やメモを通じて自分の気持ちを整理している人です。特に、今後のキャリアや生き方について考えている人を想定しています。

**その人は、どんな場面でこのアプリを思い出すか？**

- 昔好きだった作品を思い出したり、読み返したりしたとき
- 自分の生き方やキャリアに迷い、以前の自分が大切にしていたことを確かめたいとき
- 心に残る作品に出会い、そのときの感情を残したいとき

**今の生活の中で、代わりに使っているものは何か？**

非公開のメモ帳、日記、読書管理アプリなどです。

**それを置き換えてまで使う理由はあるか？**

メモや日記では、同じ作品について過去と現在の記録を並べて見るのに手間がかかります。また、読書管理アプリでは読んだ本の数や作品の評価が中心になりがちです。このアプリでは、作品にまつわる自分の体験と、その後の感じ方の変化を振り返ることに集中できます。

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ（導入・継続の流れ）

**どんな場面・困りごとがきっかけで、このサービスを知る・思い出すか？**

昔好きだった作品を読み返したときや、心に残る作品に出会い、そのときの気持ちを書き残したくなったときです。

**最初の一歩で、ユーザーは何をする必要があるか？**

心に残っている作品を1つ登録し、その作品に出会った当時の思い出や感情を記録します。今あらためて作品を見て感じたことがあれば、それも記録します。

**利用を続ける理由は何か？**

- 同じ作品を読み返した際に、新しい感想を追記できる
- 心に残った作品の記録が、思い出のアルバムとして蓄積される
- 過去の記録を読み返すことで、自分の感情や価値観の変化に気づける
- 本リリース後は、同じ作品に思い出を持つ人の感じ方にも触れられる

### 5-2. それでも自分が作りたい理由

既存サービスでは、本の評価や読書習慣の記録、次に読む本を探すことが中心になりやすいと感じています。私は、作品そのものの評価よりも、「その作品に出会ったとき、自分に何が起きていて、どう感じたか」を残したいです。

また、他人の評価が目に入ると、自分の素直な感想を書きにくくなることがあります。おすすめや新刊情報などから少し離れて、自分の思い出に向き合える場所を作りたいと考えています。

### 5-3. 差別化を「体験価値」で表現する

**私のアプリの差別化ポイント：**

昔好きだった作品を読み返した人が、当時の思い出と今の感想を並べて、自分の変化や、ずっと大切にしている価値観に気づけることです。

作品の評価ではなく、その作品とともにあった「自分の体験」を振り返る時間を提供します。

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

- **行動の変化：** 昔好きだった作品をもう一度手に取ったり、心に残る体験を書き留めたりするようになります。
- **気持ちの変化：** 忘れていた感情や思い出に触れ、過去の自分を肯定したり、自分の変化を前向きに受け止めたりできるようになります。
- **考え方の変化：** 過去と今の感じ方の違いから、自分の価値観の変化や、変わらず大切にしていることに気づけます。将来的には、他の人の記録を通じて、同じ作品にもさまざまな受け取り方があると知ることができます。

### 6-2. 価値を一文で表す

このサービスは、今後の生き方に迷いを感じている人が、心に残る作品と思い出を振り返り、自分が大切にしてきた価値観や変化に気づけるようになるサービスです。

## 8. このアプリの懸念点とその対策

### 懸念点①

- **何が問題になりそうか：** 最初の数件を登録した後、新しい記録や振り返りをしなくなる可能性があります。
- **なぜそう思うか：** 過去の体験を思い出して文章にするには手間がかかります。また、記録したいと思えるほど心に残る作品に出会う頻度は高くないため、サービスの存在を忘れてしまう可能性があります。
- **そのために考えている対策：** 感想文の入力を任意にし、感情タグだけでも記録できるようにします。将来的には、過去の記録を振り返るきっかけとなる通知や、記録が増えると本棚が埋まっていくデザインも検討します。

## 9. 今後の展開・発展の方向性

記録が増えるほど、作品を通じた自分の感情や価値観の変化を振り返りやすくなります。また、他の人が同じ作品をどう受け取ったかを知ることで、自分とは異なる経験や考え方にも触れられます。

### 今考えている発展案

**機能追加の方向性**

- 「○年前、この作品と出会いました」と過去の記録を振り返るきっかけになる通知
- XなどのSNSへの記録の共有
- 同じ作品に思い出を持つ人同士で語り合える機能
- 記録が蓄積された際に、自分の感情や価値観の変化を振り返れる機能

**UI・体験の改善**

- 記録した作品が本棚に少しずつ並んでいくようなデザイン
- 過去と現在の記録を見比べやすい表示

**機能以外の工夫**

- 本や漫画に加え、映画や音楽など、さまざまな作品の思い出を残せるようにする
- 公開する内容を自分で選び、安心して記録や共有ができる場づくりを考える

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- **フレームワーク：** Ruby on Rails
- **DB：** PostgreSQL
- **デプロイ先：** Render
- **使用予定ライブラリ：** Sorcery、i18n

### 10-2. 技術選定の比較検討

| 候補 | 採用／不採用 | 理由 |
| --- | --- | --- |
| Ruby on Rails | 採用 | カリキュラムで学んだ技術を活用でき、限られた開発期間の中でユーザー登録や記録の保存・表示を実装しやすいため |
| JavaScriptによる画面の部分更新 | MVPでは不採用 | 作品の登録や振り返りの追加は、通常のフォーム送信と画面遷移で実現できるため |
| React | MVPでは不採用 | まずはRailsでコアとなる記録・振り返りの体験を完成させることを優先するため |

**今回チャレンジしたい点**

カリキュラムで学んだCRUDや「1対多」のデータ構造を応用し、1つの作品に複数の振り返り記録が紐づく仕組みをActive Recordで実装することです。

**不安な点**

限られた期間でMVPを完成させられるか不安があります。特に、エラーの調査や既習内容を応用した実装に想定以上の時間がかかる可能性があります。

### 10-3. キャッチアップ不足の懸念

1. **完成までのハードルが高い**  
   現時点では、カリキュラムで学んだ内容を応用した実装や、自力でのエラー解決に時間がかかると予想しています。そのため、MVPではRailsやSorceryなど、学習経験のある技術を中心に使います。

2. **Issueの見積もりが難しい**  
   実装前には、どこまで理解しているか、どの部分に調査が必要かを把握しきれない可能性があります。機能を小さなIssueに分けて進め、調査に時間がかかった場合も優先度の高い機能から完成させます。

Reactなどの新しい技術は、MVPで必要な体験を完成させた後に学習・検証し、導入するか判断します。
